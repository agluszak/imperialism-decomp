# The durable class model (semantic AST + MSVC500 layout oracle + RTTI audit)

Game-class datatypes in the Ghidra DB are mostly empty 1-byte stubs — names
without layouts (see the datatype-hygiene entry in `ghidra-db-mutations.md`).
The class model replaces guessing with two strictly separated evidence layers
plus a binary cross-check, generated by `just generate-type-model`:

## 1. Semantic layer — Clang AST (`tools/class_model.py`, `just record-model`)

A real clang parse of the game headers yields, per record defined under the
repo's own `include/`: tag, base-class edges (access/virtual), field names +
type spellings + array counts + bitfield-ness, and whether the record declares
its own virtuals. Host clang is authoritative for **declarations only — its
layout is never used**. Template patterns, forward declarations, and records
from vendored SDK/MFC headers are excluded (a substring path filter once leaked
`_DPCAPS`-style system records; the filter is strict-prefix now).
Output: `build-msvc500/generated/record_model.json` (534 records, ~1.7k fields).

## 2. Physical layer — the MSVC500 layout oracle (`tools/layout_oracle.py`, `just layout-oracle`)

A generated TU (one dumper per record) is compiled **and executed** by the real
VC5 toolchain container (`imperialism-msvc500`, same include order as the game
build with the DirectX 5 SDK first, same layout-relevant flags: default `/Zp8`,
`/GX /GR-`). The program itself prints:

    RECORD|<name>|<sizeof>          BASE|<derived>|<base>|<offset>
    FIELD|<name>|<field>|<offset>|<size>
    EXTBASE|<mfc-base>|<sizeof>     (real VC5 sizes of MFC bases, e.g. CView=64)

Every number is compiler output — build evidence, never hand-written metadata
and never a host-clang guess. Members the oracle cannot measure are recorded as
`skipped` (bitfields, reference members, virtual bases) rather than invented.

VC5 gotchas encoded in the generator:
- include each header by ONE spelling (`game/X.h`) — VC5 `#pragma once` dedupes
  by spelling, so a second path to the same header causes a C2011 storm;
- `sizeof` is ill-formed on zero-length trailing arrays (`pad[0]`) — offset is
  measured, size recorded 0;
- access is widened (`#define private public`) — MSVC lays out strictly in
  declaration order, so this does not change layout;
- offsets use `(char*)&((T*)16)->f - (char*)16` (works for abstract classes).

The oracle self-validates against the decomp's own conventions: offset-suffixed
field names agree exactly (`TMission::nationId04`@4, `TView::frameWidth34`@0x34,
`TArmyMission::orderListAt18`@0x18, …).

## 3. Binary cross-check — RTTI audit (`tools/class_model_audit.py`, `just class-model-audit`)

Oracle `sizeof` vs the original binary's `CRuntimeClass::m_nObjectSize`
(`config/rtti_class_oracle.csv`). Disagreement **blocks projection** — the apply
step never silently chooses a model. Current verdicts over 534 records:

| verdict | count | meaning |
|---|---|---|
| **verified** | **312** | source declaration reproduces the original object size under the original compiler — safe to project |
| source_incomplete | 83 | oracle < binary: the source class is missing trailing fields; finish the declaration to unblock |
| source_oversized | 13 | oracle > binary: the source declares MORE than the original object (e.g. `TGreatPower` 0xb6c vs 0x964, `TMinister` 0x48 vs 0x10) — modelling errors to fix |
| no_rtti | 126 | no CRuntimeClass in the binary; oracle-only evidence, projectable with the caveat recorded |

Evidence CSV: `build-msvc500/evidence/class_model_audit.csv`.

## Next: `apply-class-model` (DB projection)

The projection step (separate PR) consumes the three artifacts: create sized
record shells, populate base subobjects (game bases flattened at oracle offsets;
MFC bases as single fields of their pack/EXTBASE-sized types), place fields at
exact oracle offsets (semantic type where it resolves at the right size, else
undefined bytes — physical truth wins), install typed vptrs, replace the 1-byte
stubs, and rewrite references. Only `verified` and `no_rtti` records project;
`source_incomplete`/`source_oversized` stay blocked until the source is fixed.
Class projection must run BEFORE signature projection in
`ghidra-apply-source-full`, so the signature projector resolves parameter types
against real layouts instead of placeholders.
